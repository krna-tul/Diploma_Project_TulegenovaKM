# Работа с прототипом платформы

Прототип демонстрирует сценарии в одном браузере. Записи сохраняются в localStorage; общий сервер, учетные записи и проверка полномочий пока не реализованы. Профили и программы демонстрационные. В новом frontend для рекомендаций используются открытые пары «курс — навык» из UniSkill; закрытые данные университета не предоставлены.

## Запуск

Требуется Node.js 20 или новее. В корне репозитория выполнить `npm start`, затем открыть http://localhost:4173. Установка зависимостей и сборка не требуются. Альтернатива: `node src/scripts/serve.mjs`. Порт по умолчанию 4173; для другого порта использовать `PORT=4174 npm start`. Сервер доступен только на локальной машине.

## Новые экраны и подбор (22 октября 2026)

Главная страница открывает frontend по 11 PNG-макетам. Для проверки рекомендаций:

1. Нажать Create mentee form.
2. Раскрыть Find recommendations by skill, найти и выбрать навык UniSkill.
3. Нажать Find recommended mentors.
4. Посмотреть View course evidence: признаки, курс, вероятность и порог 0.55.
5. Через View mentor profile выбрать предпочтительного наставника и сохранить запрос.
6. При необходимости изменить привязки через Manage demo course assignments.

Для просмотра проверки Школы и УМО открыть Demo workspaces внизу страницы либо переключить роль через аватар. Формы, план и визит сохраняются локально. Экспорт CSV содержит административную сводку и не включает частные заметки.

## Исходный полный сценарий

Сценарий ниже доступен по `/workflow.html`. Он сохраняет первоначальную доменную модель и отдельное состояние localStorage. Новые формы и старый сценарий не синхронизированы.


1. На главной просмотреть навыки, выполнить поиск и выбрать направление. Витрина показывает связанные мероприятия; выбранный навык переносится в запрос.
2. Подать карточку наставника через верхнюю кнопку. В роли директора открыть «Заявки» и проверить критерии; в роли академического департамента подтвердить инструктаж. Карточка появляется в каталоге.
3. Подать запрос как наставляемый. Предпочтительную кандидатуру можно не указывать.
4. В роли директора выбрать наставника в «Заявках» и предложить пару.
5. В «Пары и планы» переключиться на наставника и наставляемого, подтвердить согласие каждого. Директор проверяет конфликт интересов и представляет пару. При превышении двух пар фиксируется согласованное исключение.
6. Регистратор вводит номер распоряжения проректора, дату назначения и конец периода.
7. Открыть план. Участники задают цель, формат и периодичность, добавляют задачу с поддержкой, сроком, ожидаемым результатом и способом фиксации прогресса. Обе стороны согласуют версию, директор утверждает ее либо возвращает с обязательным комментарием и сбросом согласий.
8. Участники фиксируют встречи; второй участник подтверждает запись. Автор не может подтвердить свою встречу. Участники фиксируют выполнение задач, начальную, промежуточную и итоговую оценку. Правка содержания плана требует новых согласий и утверждения; утвержденные версии доступны в истории.
9. Для Development Visit заполнить подготовку; наставник добавляет факты с таймкодами и критериями карты. Совместное обсуждение включает самоанализ, сильные стороны, вопрос, рекомендацию, изменение следующего занятия и способ измерения.
10. После итоговой самооценки и отзыва директор завершает программу. При необходимости участник подает обращение о замене/досрочном завершении, Школа регистрирует решение.

Запись на мероприятие находится в его карточке. Повторная запись с тем же демо-именем блокируется; количество мест проверяется.

## Покрытие и ограничения

| Функция | Реализация прототипа |
| --- | --- |
| Две формы и каталог навыков | Отправка, валидация, фильтры, переход с карточки |
| Проверка кандидата | Проверка стажа, решение Школы и инструктаж; возврат с причиной |
| Подбор | В старом сценарии — выбор Школы; в новом frontend — рекомендации по logistic regression на UniSkill |
| Согласование и назначение | Два согласия, представление, лимит, конфликт интересов, реквизиты распоряжения |
| План | Цели, задачи, сроки, поддержка, результаты, согласия и утверждение версий |
| Встречи и визиты | Сохранение результатов, подтверждение вторым участником и три этапа карты |
| Оценка и обращения | Начало/середина/итог; решение о замене; итоговое завершение |
| Аналитика | Счетчики процесса без текстов наблюдений |
| Серверный доступ | Не реализован; роль переключается для демонстрации |
| Календарь | Пн–пт; праздники и календарь AITU не подключены |
| Локализация | Русский интерфейс; схема трех языков в требованиях |
| Вложения, уведомления, экспорт | Следующий этап |
| События | Синтетический каталог и запись; редактор организатора следующий этап |

Утвержденный индивидуальный план участника не заменяет официальный Индивидуальный план работы преподавателя. Ввод номера распоряжения не создает юридически значимый документ.

## Хранение

Адреса localhost и 127.0.0.1 имеют разные browser storage; для продолжения использовать тот же адрес и порт. Возврат к чистому набору выполняется удалением данных только этого локального сайта через настройки браузера. В Git пользовательские записи не сохраняются.
