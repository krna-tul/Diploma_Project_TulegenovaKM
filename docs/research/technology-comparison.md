# Выбор технологий

Три основных решения сравниваются по требованиям ролей, транзакций, удобства разработки одним автором и проверяемости. Выбор целевой версии предварительный; прототип использует HTML/CSS/JavaScript и локальное хранение для демонстрации сценариев.

| Решение | Альтернатива | Сильная сторона | Издержки в этом проекте | Вывод |
| --- | --- | --- | --- | --- |
| Сервер | Django | ORM, формы, admin, пользователи в одном фреймворке | Нужно спроектировать API и объектные права | Предварительный выбор для монолита |
| Сервер | FastAPI | Типизированная валидация и OpenAPI | Авторизация, admin и ORM собираются отдельно | Подходит при приоритете API |
| Сервер | Express | Небольшое ядро, один язык с клиентом | Валидацию, ORM и доступ нужно выбирать отдельно | Допустимо, больше интеграционных решений |
| Данные | PostgreSQL | Связи, ограничения и транзакции | Отдельная служба и резервирование | Выбор для конкурентных согласований |
| Данные | SQLite | Файл БД, простой локальный старт | Не целевой выбор для многих конкурентных записей | Для локального стенда |
| Данные | Browser localStorage | Без серверной установки | Нет общей БД, серверных прав и транзакций | Только демонстрация |
| Клиент | React | Компоненты и управление состоянием | Сборка и дополнительные зависимости | Рассмотреть после UX проверки |
| Клиент | Vue | Декларативные компоненты и постепенное внедрение | Сборка для расширенного приложения | Равноправная альтернатива |
| Клиент | HTML/JS | Запуск без сборки и зависимостей | Ручное управление состоянием крупных форм | Выбор текущего прототипа |
| Связь | REST/JSON | Понятные ресурсы, простые интеграционные тесты | Нужны версии и ошибки API | Выбор целевого клиента |
| Связь | Серверные HTML формы | Меньше клиентского состояния, CSRF в Django | Менее гибкие интерактивные планы | Запасной вариант монолита |
| Связь | GraphQL | Гибкие выборки | Дополнительная модель доступа и complexity | Не оправдан для первой версии |

Архитектурное решение: модульный монолит Django + PostgreSQL с REST API, клиент после проверки прототипа. Это сокращает эксплуатационную сложность одного дипломного проекта. Микросервисы и интеллектуальный подбор исключены из первой версии. Серверный стек пока спроектирован, не реализован.

Основания: [Django overview](https://docs.djangoproject.com/en/5.2/intro/overview/), [FastAPI features](https://fastapi.tiangolo.com/features/), [Express](https://expressjs.com/), [PostgreSQL constraints](https://www.postgresql.org/docs/current/ddl-constraints.html), [SQLite Python interface](https://docs.python.org/3/library/sqlite3.html), [React](https://react.dev/learn), [Vue](https://vuejs.org/guide/introduction.html). Сведения проверены 10 октября 2026; сравнительные оценки являются проектными выводами, не результатами нагрузочного теста.
